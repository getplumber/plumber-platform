## Plumber Platform v2.0.0

First release of the v2 line of the self-managed Plumber Platform: the control plane that ingests
the analysis results the open-source [Plumber CLI](https://github.com/getplumber/plumber) pushes
from your pipelines, then governs policies, detects drift and proves coverage. Analysis stays in
the CLI; the Platform never re-evaluates it.

v2 is a new product generation. It is not compatible with the v1 line, does not share its
database, and has no automated migration. v1 keeps living, unchanged, in
[getplumber/platform](https://github.com/getplumber/platform).

### What ships

- Images `docker.io/getplumber/platform-backend:v2.0.0` and
  `docker.io/getplumber/platform-frontend:v2.0.0`, built from one monorepo commit and always
  released together on one version.
- Docker Compose install with bundled Traefik (Let's Encrypt or your own certificates, bundled or
  external PostgreSQL), an interactive installer, and update, backup and restore scripts.
- Helm chart `plumber-platform` 2.0.0, published from this repository's Helm index
  (`https://getplumber.github.io/plumber-platform`), with optional bundled PostgreSQL and Redis,
  private CA support and a one-shot bootstrap Job.

### Highlights

- Native CI OIDC ingestion: pipelines push results with their own identity token; no shared
  secret in runners.
- Policies, portfolios and custom controls managed in the Platform (no config repository).
- Governance on the default branch, per-branch views, issue tracking with automated fix flows,
  freshness and staleness tracking, scheduled reports.
- Hardened ingestion: structural caps on the untrusted push body, generic rejections, per-reason
  metrics.
- Observability: Prometheus metrics on `/metrics`, liveness `/healthz`, readiness `/readyz`.
- Air-gapped friendly: private CA trust for GitLab and SMTP, update check disabled with one
  setting.

### Requirements

- GitLab 15.7 or later (native `id_tokens`); 16.x for CI/CD components, 17.x for `spec:inputs`.
- Docker with the Compose plugin 2.20 or later, or Kubernetes with Helm 3.
