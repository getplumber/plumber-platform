

### New
- The platform stores and shows the score the CLI computes for each policy (letter, points and the formula behind them) together with the attack paths, situation and best fix that explain it, instead of recomputing a score of its own; the minimum-points gate reads the pushed points; issues carry their base severity beside the shown one, with a filter; and the plumber_score_withheld_pushed_grade_total metric is back on /metrics.
- A project whose CI configuration path points at the instance's central file is now detected, collected and resolved through that file; any other external file is not read.
- A git instance can integrate projects through their CI configuration path: Settings chooses the mode and the central file (with its check and a snippet), onboarding writes the project's setting and starts its first run instead of opening a merge request, and unboarding resets it.
- Settings and the onboarding wizard let an administrator choose how Plumber reaches projects, a merge request per project or one central CI configuration file every project points at.
- The onboarding wizard's Plumber component step is complete only once the central CI configuration file, when that method is chosen, has been checked and includes the component.
- The onboarding wizard's deploy step and its result say whether a merge request opens or the project's CI configuration path is written, following the instance's integration method.
- The onboarding dialogs say whether a merge request opens or the project's CI configuration path is written when the caller is an administrator, and stay neutral otherwise.
- Unboarding a project integrated through its CI configuration path says the path is reset instead of a merge request, and offers no merge action for it.
- Projects integrated through their CI configuration path carry a Central CI config marker on the list and the issue panel, and the project page says how it was integrated.

### Fixes
- The component pin's note for a resolved version says the tag is verified at deployment time, which covers the central CI configuration method too.
- Policies created from the ISO27001, SecNumCloud and OWASP templates no longer flag the Plumber job itself: their image source control trusts the getplumber/plumber image.
